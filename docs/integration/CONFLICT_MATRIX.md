# Integration conflicts and resolutions

| Conflict | Evidence | Resolution and gate |
|---|---|---|
| File/state architecture | All donors edit `app/page.tsx`, `app/scene.tsx`, `app/anatomy.ts`; wiiiimm model switching resets `SceneState`, MVMT adds chunk/depth/line/focus, PR #1 region/area, PR #421 hidden | Define typed model registry, navigation state and visibility reducer first. Port each behavior behind interfaces; do not merge files. |
| Renderer and Three version | wiiiimm `package.json`/lockfile Three `^0.185.0`; MVMT and upstream `^0.159.0`; MVMT scene has custom materials, ghost/context, lazy chunks | Keep r185 baseline. Port/retest shader hooks and material behavior against r185. No dependency downgrade. |
| Manifest and chunk scheme | wiiiimm three manifests with 15/10/17 chunks; MVMT one 36-chunk male manifest plus overview/context; PR #283 appends a 16th male chunk | Stable `ModelAsset`/`GeometrySet` descriptor; model-specific loader. Preserve existing shipped manifests until validated conversion. |
| Part versus concept IDs | `FJ*`, `VH*`, `ZN*`, `ZA*`, `NV*`, `SC*`, `LM*` parts; BP3D FMA concepts, HRA FMA/UBERON, MVMT custom IDs; `scripts/build-index.mjs` matches names | Internal canonical concept ID with typed source-ID crosswalk and explicit match status; mesh instances keep original source IDs. Never use names alone. |
| Search/selection | wiiiimm search groups pin `FJ*`; MVMT bridge can map a structure to several parts and uses parent data; PR #1 regex finds areas | Search canonical concepts and aliases, then resolve to available model meshes. Missing-geometry concepts remain searchable and labeled. |
| Regions | MVMT nine region chunks versus PR #1 six centroid regions | One anatomical region taxonomy. Region membership is curated concept relationship; geometry coverage and fetch groups are separate model-specific mappings. |
| Teaching areas | PR #1 regex can collect nonlocal lookalikes and its brachial plexus is a corridor lacking trunks in baseline | Import 17 area labels as candidates; publish only reviewed concept IDs, contextual structures, side and evidence. Do not imply a mesh exists. |
| Visibility and dissection | Baseline systems/breast/isolate/explode, PR #421 hidden, MVMT hiddenParts/depth/line/region/context | Compute one derived visibility/pickability decision with precedence; hidden is model-scoped and wins over selection until explicit restore. Explosion uses exactly the visible full-detail set. |
| Supplemental geometry | MVMT Z-Anatomy fit to male, schematic nerves and derived patches; PR #283 source-derived tubes; wiiiimm has separate female experiment | Use per-asset registration, fidelity and license metadata. Compare alternatives by concept/side. No male spatial asset on female without independent transform and review. |
| Duplicate nerve representations | MVMT 8 bilateral schematic peripheral nerve groups; PR #283 has 27 bilateral named groups and overlaps those 8 conceptually | One canonical concept may have multiple geometry representations, but choose a default per model and allow explicit provenance/fidelity display. Do not render duplicates by default. |
| Naming and content quality | MVMT 445 `latin`/`action`/`clinical` entries from `mvmt-program`; PR #1 names used as selectors | Store text in reviewed, cited knowledge records; label imported prose draft and clinical claims unverified. |
| System reclassification | MVMT retains all 2,234 `FJ*` IDs but reclassifies 14 skeletal parts as muscular and two as fascia (`scripts/overrides.mjs`, manifest comparison) | Keep source system, canonical anatomical classification and viewer display layer as separate fields; review each override rather than overwriting original metadata. |
| Build tooling | MVMT `merge-layers.mjs`/`build-index.mjs` require external generated files; wiiiimm local female scripts; PR #283 needs Blender export | Keep reproducible source assets/hashes and CI validation before promotion. Do not run scripts that mutate model chunks during this audit. |
| License boundary | Code MIT; BP3D/HRA CC BY; Z-Anatomy CC BY-SA; MVMT fitted assets lack complete in-tag chain | Maintain asset-level provenance and separate distributable bundles. Legal/source review before packaging share-alike or third-party geometry. Preserve existing attribution. |

Highest risk: female registration of male-fitted overlays; MVMT source/provenance chain; duplicate/unequal nerve fidelity; and replacement of the loader/visibility stack across Three versions. These gates precede any geometry publication.
