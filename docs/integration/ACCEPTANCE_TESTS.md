# Acceptance tests for integration phases

Tests below are proposed gates for **future** phases. This audit itself only runs nondestructive baseline checks. Maintain a frozen manifest summary and a small reviewed visual set for all three current models. Test on desktop and touch-sized viewports where interaction matters.

| Gate | Required assertion |
|---|---|
| Repository health | `npm run check`, `npm run build`, existing `scripts/validate-atlas.mjs`, `scripts/validate-interactions.mjs`, and package test scripts pass with pinned Node/dependencies. Build leaves source and geometry unchanged. |
| Manifest/geometry integrity | Every chunk exists/decompresses; offsets, lengths, index bounds, bounds and part/concept references are valid; expected counts 2,234 male, 888 HRA female, 2,245 female study; source hashes and transformation reports match promoted assets. Detect duplicate IDs and missing IDs. |
| Model loading/switching | `/male` and `/female` load; the bundled but currently unrouted `female-reference` manifest validates. Phase 1 explicitly decides whether to expose a route/selector choice. Repeated switches do not leak previous chunks or hidden part IDs. Concept selection resolves on new model or reports unavailable. Preserve stage/camera defaults and failed-load recovery. |
| Core interaction | Search by English/Latin/alias/source ID, select single and multi-mesh concept, isolate, clear selection, system filter, explode from 0–100%, reset and camera orbit/zoom; selected/visible counts agree with renderer. Existing `scripts/anatomy-search.test.mjs`, `scripts/cursor-zoom.test.mjs`, `scripts/chest-visibility.test.mjs` are useful regression checks. |
| Female behavior | HRA and study systems, breasts/cutaway/muscle presentation, reproductive organs and knee additions retain documented behavior; run `validate-female-readiness.mjs`, `validate-female-joint-additions.mjs` and focused female tests. Show experimental status for study mesh placement. |
| Region/area | Each reviewed concept can belong to zero or more regions/areas; all 17 areas have reviewed focal/context membership or are explicitly pending. Brachial plexus station spans region boundaries; Orbit/Hand/Foot exclude unrelated name matches. Whole-body and region chunk modes resolve the same concept IDs and side. |
| Visibility/dissection | Hiding selected mesh leaves neighbors; restore restores it; isolate cannot reveal a user-hidden mesh implicitly; search can offer explicit restore; system, depth, region and area filters compose; hidden parts are not pickable or packed into exploded view. Reset semantics and model switching are deterministic. |
| Nerves and supplemental geometry | A nerve has correct side, selected source/fidelity label, no default duplicate of overlapping MVMT/PR #283/BP3D representation, valid fit report and visible path at correct scale. No male-registered set appears on female without a separately approved registration. Low-confidence assets are labeled or excluded. |
| Knowledge/provenance | Every published description/Latin/clinical assertion cites a source and review status; missing knowledge falls back without fabricated text. Every loaded asset has source revision, hash, license, attribution and adaptation note; generated credits match active model/sets. |

Suggested interaction matrix: `model × search/selection × system on/off × region/area × isolate × hidden × explode × reset`. Full Cartesian testing is unnecessary; pairwise coverage plus targeted high-risk sequences is adequate. Highest-risk sequence: select nerve → hide → search it → isolate → explode → switch female → reset → switch male, checking that neither hidden state nor male coordinates bleed across models.

## Audit baseline verification

This phase must not mutate `public/models` or application source. Run type check, build, manifest validation and the existing viewer/female checks that can run locally; record failures as baseline failures. Use `git status --short` and `git diff --name-only` afterward to confirm only `docs/integration/` was added. Visual/browser checks for all models remain a Phase 1 prerequisite if a browser harness is unavailable in this audit environment.
