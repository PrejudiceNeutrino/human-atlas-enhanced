## Baseline separation

The wiiiimm manifest has shared fields (`Part`, `Concept`, chunks, system IDs) and shared viewer logic, but `app/page.tsx` chooses a different manifest per model. `atlas-female.json` uses `VH*`, `Allen*` and `Yale*` mesh IDs with FMA/UBERON-like concept IDs; the reconstruction mixes 2,181 retained `FJ*` parts with 64 `VH*` parts. `scripts/build-female-reconstruction.py` excludes male-specific parts, fits HRA pelvis/reproductive/breast structures, morphs retained male geometry, and adds two experimental knee ligaments. `public/models/female-fit-report.json` and `public/ATTRIBUTION.md` label its placement and proportions experimental. Search group membership is pinned to BodyParts3D IDs and verified names (`app/anatomy-search.ts`), so its UI is shared while mapping coverage differs by model.

**Route gap:** `web/main.tsx` accepts `/male` and `/female` only; the selector in `app/page.tsx` exposes those two values. The `female-reference` type and `atlas-female.json` fetch path are present, but the HRA reference is not reachable through the shipped routes. Preserve the asset and test it as a data input; Phase 1 must decide whether and how to expose it.

`upstream/main` and the three PR tags are upstream-lineage reference points, **not** descendants of the chosen wiiiimm HEAD. `git merge-base upstream/main donor/wiiiimm-base` is `1c38bf35c254a891200d3cedecfd57abebe83d8d`. MVMT is also based on upstream; its own `main` diverges and removes female assets. The snapshot tag, not a current remote branch, defines each donor.
